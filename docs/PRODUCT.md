# Burrow product strategy

This is the source of truth for what Burrow is for, who it is for and what it costs (nothing: Burrow is free for everyone since 2026-11-05). Every contributor and every AI agent working in this repo should read it before planning work. If a task conflicts with this document, stop and flag it instead of guessing.

Owner: Christian Munoz. Last updated: 2026-11-05.

## Mission

A 100% private, local-first budget and journal tracker for **mainstream consumers**. Everything runs on the user's own computer by default. No accounts, no telemetry, and no cloud unless the user brings their own cloud AI (opt-in, see the 2026-10-05 decision).

Positioning: an ethical alternative to predatory cloud finance and journaling apps. The hook is **"Zero subscriptions. 100% privacy."**

## Product principles

0. **"I downloaded the app, I opened it, and it just worked."** (owner, 2026-10-05) This is the north star for every feature. No terminal, no configuration, no accounts, no setup screens before the app is useful. Sensible defaults everywhere; every setup step that remains is optional, skippable and done in-app with one click; every error says exactly what to do next. A feature that needs the user to configure something before it helps is not done.

1. **Local-first, always.** Data lives on the user's machine in open formats (SQLite, JSON, CSV, Markdown). No outbound call without an explicit, labelled opt-in (`server/netPolicy.js`).
2. **The user's data is never paywalled.** Burrow is free for everyone; export, import, backups, privacy controls (including saved API keys, which are stored encrypted) and the audit log stay free forever.
3. **AI summarizes, code calculates.** LLMs hallucinate numbers. All math (totals, averages, comparisons, dates, budgets) is computed natively in SQL or JS first. The model only receives precomputed results and turns them into words. Never ask a model to add, subtract, compare or count. Output sanitizers (`$` formatting, no em-dashes) still apply.
4. **Data must never be lost.** Budget and journal data is sensitive and fragile. Burrow keeps automatic daily local backups with rollback (dated `.db` snapshots plus a JSON export), runs a backup before every migration and offers one-click restore. This is part of the free core.
5. **Works on ordinary hardware.** Mainstream machines vary wildly. Default to small, efficient local models, pick models by available RAM, and handle slow CPU-only inference gracefully (clear progress, generous timeouts, a friendly "Javi needs Ollama" state, never a raw error).
6. **Trust through transparency, with control over the private module.** Everything that touches the user's data or the network (storage, backups, export/import, netPolicy, the audit log, the AI boundary and cloud consent) is public and auditable under AGPL-3.0-only in the core repository (https://github.com/ChristianMunoz31/burrow-core). Some features live in a private module that can only reach data and the network through those public core APIs, and this rule is enforced in our build. The module's source is not public. Trust also comes from verifiable behaviour: a Network activity page, a "verify it yourself" guide, release checksums, and a public changelog and issue tracker. Burrow contacts no store and has no license check.
7. **$0 marginal cost to the developer.** Features run on the user's hardware and storage. Avoid anything that creates ongoing hosting, per-user API or store fees unless the owner explicitly approves it.

## Delivery

- **Mainstream users get a one-click desktop app** (Tauri wrapper around the Burrow UI and server) that talks to the user's local Ollama install behind the scenes and guides them through installing Ollama and a model.
- **Docker is internal and for prosumers.** It is an internal dev and test setup, not offered for self-hosting and not the consumer path.
- **Docker images built with `pro/` are internal only and are never published to any registry** (owner decision O7, 2026-11-04). The runtime image holds the private module's server source, so such an image never leaves the owner's machines. An image built without `pro/` is a core-only image.
- **Local stable builds without `pro/` are core-only builds** (`BURROW_PRO=off`, owner decision O6) and are never publishable: every official release path (`release:auto`, `release:local`, `release:installer`, `release:store`, the release workflows) refuses to build without `pro/`.
- **The release zip is core-only source** (core source plus the core-only `dist/`, owner decision O1), attached to the private release only. It never contains the private module.
- Hardware tiers for the default local model (to validate with `node pro/scripts/evalAi.js`, see `docs/EVALS.md`):
  - 8 GB RAM or less: a 1B to 3B model (for example Llama 3.2 1B or Llama 3.2 3B) for chat; tool use limited or confirmation-heavy.
  - 16 GB RAM or more: a 7B to 8B tool-capable model for Javi's tool use.

## Monetization

- **Free for everyone (owner decision, 2026-11-05, [ADR 0002](adr/0002-free-for-everyone.md)).** Burrow costs nothing: no paid tier, no trial, no license keys, no activation, no Buy button and no upgrade prompts. Every feature (Javi questions and approved changes, daily briefings, Explain, folder questions and reports, the Javi characters, the founder theme) is on for every install of an official build, with no time limit. The $0 marginal cost rule (principle 7) stays: no hosted services, per-user APIs or store fees without owner approval.
- **Open core (core published under AGPL-3.0-only; a private module).** Some features live in a private module (`pro/`, its own private repo `burrow-pro`) that is compiled into official builds at no cost and can reach data, the network and AI only through a named list of core APIs (`docs/OPEN_CORE.md`). The only remaining condition is technical: whether the module is compiled into the build. A core-only build says "not included in this build" and never offers to buy or upgrade. The core is published under AGPL-3.0-only at https://github.com/ChristianMunoz31/burrow-core (2026-11-04; owner runbook: `docs/PUBLISHING_CORE.md`); the private working repo keeps the name `ChristianMunoz31/burrow`. Copy may say the core is open source and AGPL. The module's source is not public, so copy never says it is open source or that its source is public, and it never offers Docker self-hosting. Developer tools live in `devtools/`, which is never part of the public core or of any stable build.
- **Licensing:** see [LICENSING.md](LICENSING.md). There is no license subsystem, no store call and no `config/store.json`; the support address lives in `config/support.json`.

## Go to market

1. Seed trust with prosumers: launch in r/LocalLLaMA and r/selfhosted with the verification guide, release checksums and a public changelog; the core source is public on GitHub under AGPL-3.0-only, while the module for some features is private.
2. Scale to mainstream with short-form videos about data ownership and "zero subscriptions".
3. Public roadmap and a plain "what we never collect" page.

## Pitfalls to design against

- **Hardware variance:** never assume a GPU or lots of RAM. Test on CPU-only 8 GB machines.
- **AI math:** see principle 3. Any feature that sends numbers to a model must precompute them and have a test proving the model is not asked to calculate.
- **Data fragility:** see principle 4. Every schema migration needs a backup and a tested rollback.
- **Trust erosion:** no telemetry, no dark patterns, no surprise network calls, no paywalling of user data.

(5) *`nomic-embed-text` approved as is:* downloaded only on its own click; the UI states that it runs on this computer and that Ollama downloads it once (about 270 MB). (6) *PDF and DOCX text extraction (off by default since 2026-10-09, see the entry below).* Text is read from PDF (`unpdf`, MIT, which bundles PDF.js, Apache-2.0) and DOCX (the existing `fflate`, MIT, plus a small text reader) on the server only, never in the app's web bundle, in a separate worker per file with a 20 s timeout, a memory cap, at most 200 pages, 25 MB per document and zip-size guards; no network, fonts or scripts are loaded. ## Open decisions (owner must resolve; do not implement either side until decided)

1. **What the paid tier is:** resolved, then removed: there is no paid tier since 2026-11-05 (see the decisions log). The core source is public under AGPL-3.0-only and buildable by anyone.
2. **Desktop code signing cost:** unsigned installers trigger OS warnings that will scare mainstream users. Signing costs roughly $99/yr (Apple) and about $10/mo (Windows, Azure Trusted Signing). This conflicts with principle 7 and needs an explicit owner OK before a public desktop release. Unsigned builds are fine for internal testing.
